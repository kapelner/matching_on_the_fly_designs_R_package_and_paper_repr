Status: EDI Python bindings do not exist yet

EDI's C++ model-fitting kernels have no Python bindings yet, and the python/ scaffold's nascent fast_math pybind11 stub only binds one utility function (fast_pchisq_upper, not used by any row below) — see package_metadata/python_bindings_package_spec.md. Every row's EDI Time is therefore NA in all three tables today by construction, not because of a failed fit: time_edi() in this script is a single, clearly-marked no-op returning NaN. Once a kernel is bound, wiring it in is a one-line change per row (the edi_kernel field in each spec list already names the target edi_kernels.* function) — flip EDI_PY_AVAILABLE = True and pass the real fit closure. Until then, these reports document what the canonical Python baselines cost today, and which model families/functions have no canonical Python baseline at all (regardless of EDI bindings).

Benchmark Dataset Specification

  • Sample size (N): 1,000 subjects for most families; 500 for survival families and the Wilcoxon Hodges-Lehmann row (O(n²) pairwise-difference computation, matching the R harness's scale = 0.5); 5,000 elements for the utility-function vectors.
  • Predictors (p): intercept + a balanced binary treatment + 4 continuous covariates ~ Normal(0, 1); covariate coefficients ~ Normal(0, 0.5); treatment coefficient fixed at 0.5.
  • Same family-generation formulas as benchmark_model_fits.R (logistic/log-binomial/identity-binomial links, Poisson mean model, Beta(mu*phi, (1-mu)*phi) proportions, exponential survival times with ~20% censoring, 3-level ordinal construction).
  • Stratified Cox exception: a low-cardinality (2x3) strata grid is injected before outcome generation, matching the R harness, so the row exercises a genuinely stratified fit.

Methodology

  • Bare-metal canonical timing: each canonical row constructs the model object and calls its lowest-level .fit()/equivalent directly on pre-built NumPy arrays (or, where the package requires it — lifelines, statsmodels.OrderedModel internals — a pre-built pandas.DataFrame), inside the timed region only; data generation happens once, outside the timed closure.
  • Point-estimate vs. Wald tables: the point-estimate table times a bare fit (matching each row's fastest available canonical entry point — lstsq instead of OLS().fit() where that's a real, distinct fast path); the Wald table times a full fit that also produces the treatment coefficient's standard error and two-sided p-value (.bse/.pvalues off the same fitted result for most statsmodels families; a package switch to lifelines.CoxPHFitter for the unstratified-Cox row specifically, since scikit-survival's bare-metal CoxPHSurvivalAnalysis doesn't expose a variance; a finite-difference delta-method SE for the four G-computation rows, off .cov_params()). The Wald table's row set matches R's wald_specs exactly (41 classes) rather than reusing the point-estimate table's 40 — it adds several nonparametric-test-only classes with no point-estimate-table row at all (pooled-variance t-test, Wilcoxon rank-sum, Lin's estimator, Fisher exact, Miettinen-Nurminen/Newcombe risk-difference CIs, Jonckheere-Terpstra, Ridit, Gehan-Wilcoxon, KM median difference) and omits several point-estimate-table rows that R's own Wald table never covers (identity-binomial, modified Poisson, fractional logit, ordered probit, cauchit, cloglog). One row, restricted-mean-survival-time difference, is excluded from the Wald table for the same reason R's own Wald table excludes it — see below.
  • Utility-function timing: each row calls the scipy/numpy vectorized function once over a fixed-length input vector, mirroring benchmark/fast_math_utils_bench.cpp's apples-to-apples vectorized-vs-vectorized discipline (a scalar-loop binding would unfairly penalize a C++ side that hasn't been written yet).
  • Averaging: medians over 30 cold timing samples via an adaptive-batch time.perf_counter harness (mirrors the R harness's adaptive system.time split, target 200ms/batch).
  • Significance: Welch's two-sample t-test (scipy.stats.ttest_ind(..., equal_var=False)) between the EDI and canonical timing replicate distributions — currently always NA since the EDI side has no samples yet in any of the three tables.
  • Row highlighting: light green = Speedup > 1 and Timing Pval < 0.05; light grey = NA timing comparison (EDI not bound yet, or a fit failed); light blue = no canonical Python implementation exists at all for this model family/function.
  • Package versions this report was run against: numpy 2.5.1, scipy 1.18.0, pandas 3.0.5, statsmodels 0.14.6, sksurv 0.28.0, lifelines 0.30.0.
