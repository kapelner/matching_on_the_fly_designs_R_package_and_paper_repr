* Weibull frailty's "Cond." cells are isTRUE(private$use_rcpp) — true only when the Rcpp backend is in use. On InferenceAbstractKKWeibullFrailtyIVWC specifically, this flag is set but structurally inert: that class inherits InferenceAsympLik directly (not InferenceParamBootstrap), so the parametric-bootstrap public methods that would consult it don't exist on the class at all. It's a live counter-example of chain position and flag value drifting apart.

Reading the lattice: compare the "Taxonomy" column against the capability columns within either the Wald-only tier or the full-capability tier — taxonomy ranges freely (None → Partial → Combined → Full) while every capability column stays constant across the tier. Then compare the two "inside InferenceParamBootstrap" tiers against each other — same class-chain position, opposite capability. Capability is set by the boolean flags, not by depth in the inheritance chain or by likelihood taxonomy.
